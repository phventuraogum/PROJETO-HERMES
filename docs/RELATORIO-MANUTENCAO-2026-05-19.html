Segurança crítica · épico P3 5 tickets

MAI-04REVOKE EXECUTE exec_sqlP0

Função exec_sql(text) era exposta para qualquer cliente anon/authenticated via PostgREST RPC. Risco: SQL arbitrário rodando como owner.
Antes
CREATE FUNCTION public.exec_sql(text)
  SECURITY DEFINER ...
-- Default Postgres: PUBLIC tem EXECUTE
-- → anon e authenticated chamam livremente
Depois
REVOKE ALL ON FUNCTION public.exec_sql(text)
  FROM PUBLIC, anon, authenticated;
GRANT EXECUTE TO service_role;
-- Backend só · zero risco de injeção via REST
scripts/security_revoke_exec_sql.sql · commit 15d18ca

MAI-11RLS apertada por org_idP0

Policies originais permitiam acesso total via USING (true) em pipeline_leads/leads_outbound/sdr_activities. Qualquer user autenticado lia dados de outras orgs.
Antes
CREATE POLICY "pipeline_leads_select"
  ON public.pipeline_leads FOR SELECT
  USING (true);  -- ❌ todas as orgs visíveis
Depois
CREATE POLICY "pipeline_leads_select"
  ON public.pipeline_leads FOR SELECT
  USING (org_id = ANY(public.my_org_ids()));
-- ✅ user só vê leads da própria org
